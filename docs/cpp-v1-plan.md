## 0. 一页摘要

- **能做，但顺序必须是：先冻结、再切片、后铺开。全量重写是错误选项。**
- 工作量：**v1.0 约 780 人时（26 人周）**，含 10% 缓冲约 860 人时；直播语音作为 v1.1 再加约 100 人时。
- 日历：原计划按 20 h/周 → **约 43 周，2027-08 前后**；实际人工投入约 **10–12 h/周**（编码代理并行），目标 **2028-05 完成 v1.0**，截止 2028-07，留约 2 个月缓冲。
- 关键路径：工具链 → 推理栈 spike → OCR → 语料/规则 → NMT → 行为对齐 → 悬浮窗 → 打包。
- 三条军规：
  1. **契约冻结之前不写 C++ 业务代码。** 契约今天还在变（`OverlayStats.mode`、呈现文件热重载）。
  2. **行为一致性用黄金样本证明，不靠"看起来对"。** 目标 ≥98%，术语保护 100%。
  3. **UI 最后做，且只做 Windows。** 先让 C++ 引擎在现有 Python 悬浮窗后面跑通。

> **对上一轮口头估算的修正**：W0 不是"1–2 周"，按 WBS 摊开是 **90 人时**——20 小时/周下约 4.5 周。实际 W0/W1/W2 已提前完成，瓶颈已转到 UI 收尾与发布硬化。
> 原因很具体：CTranslate2 的 C++ 侧要自己从源码构建，契约导出成 JSON Schema 也不是半天的事。以本文件为准。

## 1. 目标与范围

### 1.1 产品目标

v1.0 = 能在自己机器上长期用、也能发给别人装的 Windows 桌面程序：

- 热键选区 → 屏幕 OCR → 语料/规则 → 本地 NMT → 双语悬浮窗；
- 默认全链路离线，模型一次性获取后不再联网；外部后端可选、默认关闭，开启时明确提示数据去向；
- 可解释：每行字幕带来源（语料/规则/模型）、置信度、延迟；
- 可定制：语料库、规则、呈现规格、配置档。

### 1.2 v1.0 做什么

| 能力 | 验收形态 |
| --- | --- |
| 屏幕捕获 | 区域选区、窗口跟随、多显示器 DPI 正确 |
| OCR | PP-OCRv4（ONNX Runtime），1200×200 区域 P50 ≤120 ms |
| 语料库 | 分层加载、热重载、多义项（场景/条件）、冲突可见 |
| 规则引擎 | 词缀 / 词素 / 模板 / 音译，置信度与兜底原因可查 |
| 本地 NMT | NLLB int8（CTranslate2），术语保护 100%，批量翻译 |
| 事件契约 | v1 信封（v/seq/ts），JSON-lines 可被现有 Python 界面直接消费 |
| 悬浮窗 | 点击穿透、置顶、逐行/原位、呈现规格热重载 |
| 设置 | 由 schema 驱动，键名与默认值与原型的 schema 一致 |
| 分发 | 安装包、签名、卸载干净、离线可用 |

### 1.3 v1.0 明确不做

| 不做 | 原因 |
| --- | --- |
| Linux / macOS | M5 未开始；先证明 Windows 一条腿能站住 |
| Android | 实验性目标，与 v1.0 无关 |
| 插件沙箱 | 需要进程外宿主，是 v1.1 的独立工作包 |
| Web 面板 | 继续由 Python 侧提供，C++ 不背 HTTP 服务 |
| 流式逐词字幕 | 会成倍增加 ASR 工作量并让行闪烁，原型的结论是不做 |
| 说话人分离 | 同上，v2 再议 |
| 外部 API / 局域网模型服务 | v1.0 不实现；只保留 `Translator` 接口，外部后端默认关闭，排到 v1.1 评估 |

### 1.4 与原型的关系

原型是**参考实现 + 行为规范**，不是移植源。真正要移植的是三样东西：

1. **契约**（事件/命令信封、设置 schema、呈现规格）；
2. **黄金样本**（输入 → 期望输出的判定向量）；
3. **实测参数**（OCR 线程数、det limit、beam、变化检测阈值）。

不移植：tkinter 控件树、Python 动态导入、GIL 时代的线程模型、进程内 Web 面板。

## 3. 架构决策（W0 内定稿）

| ID | 决策 | 选择 | 理由 | 被否方案 |
| --- | --- | --- | --- | --- |
| ADR-001 | 推理栈 | ONNX Runtime（OCR）+ CTranslate2（NLLB/Whisper） | 与原型的模型文件格式完全一致，零转换 | Paddle Inference、llama.cpp、ONNX 导出 NLLB |
| ADR-002 | 契约边界 | 事件信封是唯一界面；引擎不引用 UI | 原型已证明五套界面可共用同一 schema | 每层各自定义 DTO |
| ADR-003 | UI 技术 | Qt6（LGPL 动态链接）为主，Win32 分层窗兜底 | 点击穿透/置顶/逐行/DPI 都有现成能力；2 天 spike 定稿 | 纯 Win32、WebView、Electron |
| ADR-004 | 依赖管理 | vcpkg manifest，锁版本 | 可复现构建；CI 与本地同一份锁文件 | 手写 find_package |
| ADR-005 | 插件 | 进程外受限宿主，v1.1 | 这是 Python 做不到、C++ 才值得做的事 | 同进程 dlopen |
| ADR-006 | 模型分发 | 哈希清单 + 来源 + 许可 + 离线开关 | 现在 `fetch_model.py` 没有哈希校验 | 静默下载 |
| ADR-007 | 数据 | JSON 语料/规则 + SQLite 缓存，格式与原型兼容 | 用户已有词库不能作废 | 自定义二进制格式 |
| ADR-008 | 翻译后端 | 统一 `Translator` 接口；默认本地，外部 API 与局域网模型服务为可选后端 | 同一契约下可比较本地/远程；云不进入默认路径 | 为每家 API 写专用链路 |

**ADR-001 的兜底**：如果 CT2 的 C++ 构建在 spike 里超过 3 天仍不收敛，改为"ONNX encoder/decoder 双 session + 手写 beam search"。代价约 +40 人时，但依赖只剩 ORT 一个。

**ADR-008 的边界**：v1.0 只保证 `Translator` 可替换，不实现任何网络后端；外部/局域网后端默认关闭、只发送识别文本、密钥不写入配置。设置接口与应用协作接口同样只做契约预留，不在 W1 写代码。

## 6. 验收标准（v1.0）

**性能预算**（1200×200，字幕级画面）

| 指标 | 目标 | 上限 |
| --- | --- | --- |
| OCR P50 / P95 | ≤120 / ≤180 ms | 150 / 250 ms |
| 端到端 P50 / P95 | ≤150 / ≤250 ms | 200 / 350 ms |
| 冷启动 | ≤2 s | 3 s |

| 常驻内存 | ≤1.2 GB | 1.5 GB |
| 空闲 CPU | ≤2% | 5% |
| 安装体积 | ≤120 MB（不含模型） | 200 MB |

**质量**

- 黄金样本 ≥98%，术语保护 100%；
- 8 小时 soak 无崩溃、无泄漏；
- 崩溃率 <0.1%/会话（有 minidump 可归因）；
- 所有面向用户的错误必须带可操作的一句话，不允许"未知错误"。

**合规**

- 第三方许可清单完整，SBOM 可导出；
- 模型来源与哈希可核对；
- 默认零网络请求，除用户显式触发的模型下载。

| L3 契约回放 | 录制 `--json-lines` 流 → 回放给客户端 | 每次提交 |
| L4 端到端 | 合成帧 + 真实屏幕各一组 | 每日 |
| L5 长稳 | 8 小时 soak、切显示器、睡眠唤醒 | 每里程碑 |

**CI 矩阵**：Windows（编译 + L1/L2/L3）、Linux（仅编译，防止平台假设蔓延）。覆盖率不作为门槛，防止为了数字写空测试。

## 9. 流程与治理

- **契约变更**：任何 `events/settings/presentation` 改动走 RFC（`docs/rfc/`），升版本号，重生成黄金样本；未走流程的改动不合并。
- **ADR**：架构决策记在 `docs/adr/NNN-title.md`，一条决策一个文件，写清"被否方案"。
- **分支**：`main` 常绿；功能分支短命；合并前必须 L1–L3 绿。
- **节奏**：每周一次 30 分钟复盘，只看三件事——本周人时、里程碑偏差、新风险。
- **原型冻结**：W0 之后 `prototype/` 只接受 bugfix 与安全修复，不再加功能。这是整个计划里最容易破的一条。

## 10. 反模式清单（明确不要做）

1. 把 Python 逐行翻译成 C++——会把 GIL 时代的妥协一起搬过来。
2. 先搭"完整架构"再写功能——三个月后会得到一套漂亮的空壳。
3. 引擎和 UI 同时开工——两条战线同时不收敛。
4. 在 C++ 里手写 JSON/字符串/GC——用 nlohmann/json 与 RAII，别自造轮子。
5. 沿用 CMakeLists 里的 PaddleOCR / llama.cpp——那不是验证过的栈。
6. 用"能跑起来"代替"行为一致"——黄金样本是唯一证据。
7. 在 v1.0 里做插件沙箱、Web 面板、跨平台——每一件都能单独吃掉两个月。
