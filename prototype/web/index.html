词条 读取中…

你写的一切只进用户私有层的 library.json，优先级最高。 改出厂词条不会动出厂文件：它写成一条同名覆盖，标为「已覆盖」，可一键还原； 「停用」则是让出厂的某条整条不生效。 改完立刻生效（引擎按修改时间热加载，这里写完后会强制重载一次），不需要重启。

同一个词有好几条词条时，到底用哪一条（这是引擎 translate._rank 的实际顺序）：
① 层级：你写的（user） > domain > general。你自己的词条永远压过出厂词条， 哪怕出厂那条标了你正在用的场景。
② 场景：标了当前场景的 > 没标场景的 > 标了别的场景的。没选场景时这一项对所有条目相同， 也就等于不偏袒。
③ 词条自己的 priority（数字大的赢）。
④ 以上都相同，就按 origin、场景名、译文的字典序收尾， 所以答案只由词条内容决定，和文件读取顺序无关。
条件是筛子，不是排名：when_line / when_near / when_window 不成立的词条根本不进入比较（不成立就是不可用）， 只有成立的那些才按上面四条排序。 场景在「全部设置 → 当前场景（translation.scene）」里切换，当前场景： —

左侧有蓝色竖线的行是「有条件的词条」：它只在你选中的场景里、或条件成立时才生效， 和同名的通用词条不是同一条。点「编辑」可以改场景和三个条件（when_near 用逗号分隔）。

新增 / 覆盖一条

原文填出厂库里已有的词，这里保存的就是一条覆盖；填新词就是新增。 一个词有两种意思，就写两条，用「场景」或「条件」把它们分开： 场景是「现在在讲什么」（你选，全局设置），条件是引擎在行里、窗口里看得到的证据（自动判断）。
语言、场景、条件三者都相同、译文却不同的两条同名词条，是同一句话说了两遍： 引擎只能留一条，并在下面的「冲突」里告诉你丢的是哪条。条件里写正则时按整行匹配， 例如 river 会命中任何含 river 的一行；when_near 只看被匹配的词 之外的部分，所以「bank」旁边的另一个「bank」不算数。
这里写的一条词条，是按「原文 + 语言 + 场景 + 条件」定位的（和引擎一致）， 所以同一个场景里两条只有 when_* 不同的同名词条可以并存—— 这正是没有场景时表达「一个词两种意思」的写法。 反过来，改「语言 / 场景 / 条件」等于把它变成另一条：面板会写新的一条并删掉旧的那条， 删除一条时也会带上它自己的场景与条件，否则引擎不知道你指的是哪个意思。

导入 / 导出

直接粘贴：一行一条，原文,译文（或制表符分隔），也可以带表头多列； 整段 JSON 也认。不必先存成文件。

导入的 JSON 支持语料库本身的写法（{"lang": "zh-CN", "entries": {...}} 或直接的键值表）， 所以能当语料库用的文件都能直接导进来；CSV/TSV 认 source,target,lang,pos,domain,when_line,when_near,when_window,note 表头， 没有表头时按两列「原文,译文」读，多余列忽略。 其它格式（例如从别处导出的术语表）由插件的 corpus_loader 扩展点处理。
「预览」和「导入」调的是同一个接口，只多一个 dry_run： 预览会用真正的导入代码算一遍「会新增几条、更新几条、跳过几条」， 然后什么都不写。所以预览的结果和真导入的结果不会互相打架—— 但预览不改动语料库，看到数字满意了才点「导入」。
格式选「按内容自动判断」时，判断在引擎里做（{ 或 [ 开头=JSON， 首行含制表符=TSV，其余=CSV），页面只把 auto 原样发过去。 一处判断，命令行和面板同一套规则——之前是页面嗅探、引擎拒收 auto， 同一个问题两个答案。

实时纠正 —

纠正在看到错译的地方做：在字幕上选中那一行改成你要的译文，记录就写进用户层的 corrections.json，这一帧立刻改过来，以后同样的句子也用它。这里查看记录，并可以把它们提升成词条。
每条记录都带着它写下来时的目标语言：标了语言的只在译到那个语言时生效。 未标注 的记录对每个目标语言都生效—— 升级前写下的文件里全是这种，所以引擎必须继续接受它们：拒绝等于升级时静默丢掉你自己写的东西。
要让一条未标注的记录只对一个语言生效，把目标语言切到你要的那个，然后重新纠正同一条 （correct 只会盖上当时选中的语言，所以这里没有「给已有记录改语言」的按钮—— 引擎确实没有那个命令），或者直接编辑 corrections.json 给它补一个 "lang"。

「提升」到底做了什么：纠正记录和语料库是两个文件，它们各自独立—— corrections.json 里是你对着屏幕上某一句话做的修改， library.json 里是词条。提升就是把纠正复制成语料库词条： 纠正本身留在原处、照旧按它自己的规则命中，新词条则按词条规则对整段文本生效。
两者不是同一个判断：整句纠正只对那一句负责（scope=line）， 提升成词条后，凡是出现同样文字的地方都会用它；词语纠正只对一个词负责。 所以先「预览」看清会新增/覆盖几条，再决定。提升不改写纠正文件，也不删除任何纠正。
